# Mutation testing (Cosmic Ray 8.9.0)

Tool choice: Cosmic Ray. mutmut needs `fork()` and does not run on native Windows; Cosmic Ray runs here and supports custom operators.
Method: mutants run in an isolated copy of the repo (`scripts/setup_mutation_workdir.sh`) so the real tree is never mutated.
Test command: team unit tests (rules, coverage, MCC, killer tests) with a reusable on-disk test DB (`tests/team/settings_mutation.py`).
Kill rate = killed / (killed + survived + timeout). "Incompetent" mutants (invalid code) are excluded.
Raw data (all real): `reports/mutation/round{1,2}_*.jsonl|sqlite`; per-mutant analysis of every survivor:
`reports/mutation/survivor_analysis.csv` (generated by `scripts/build_survivor_table.py`).

## Scope: four business-logic modules, 551 mutants
| Module | Mutants | Round 1 (before killer tests) | Final (after killer tests) |
|---|---|---|---|
| `core/signup/flow/participant_validation.py` | 117 | 106 killed, 10 survived -> **91.4 %** | 114 killed, 2 survived -> **98.3 %** |
| `plugins/baseshiftstructures/structure/common.py` | 165 | 119 killed, 42 survived -> **73.9 %** | 152 killed, 9 survived -> **94.4 %** |
| `core/signup/stats.py` | 133 | 93 killed, 40 survived -> **69.9 %** | 133 killed -> **100 %** |
| `core/forms/events.py` (WF1) | 136 | 115 killed, 21 survived -> **84.6 %** | 134 killed, 2 survived -> **98.5 %** |
| **Total** | 551 | 433 killed, 113 survived -> **79.3 %** | 533 killed, 13 survived, 5 incompetent -> **97.6 %** |

Final rounds reran only the round-1 survivors against the extended test set (survivor results deleted from a copy of the session, then
Cosmic Ray reruns the rest). This is valid because tests were only added: a mutant killed by an existing test stays killed.
The WF1 forms module needed one extra pass (round 2 left 3 survivors; one of them exposed a test whose data made two operators agree; fixed and rerun).
**100 % statement and branch coverage was already reached on all four modules before round 1, yet 113 behavioural gaps existed.**

## Custom operators (`tools/team_mutation/`)
| Operator | Business rule | Mutants | Outcome |
|---|---|---|---|
| `team/RaiseToReturn` | error signalling (the DEFECT-001 class) | 16 | 13 killed, 2 incompetent, **1 survived then killed** |
| `team/StateConstantSwap` | BR3 participation states | 20 | 20 killed |
| `team/RuleBoundaryShift` | BR1/BR4/age boundaries | 4 | 4 killed |

The one custom-operator survivor was `raise ValidationError(...)` -> `return ValidationError(...)` in `EventTypeForm.clean_color`. The form still came out invalid
because the model's `max_length` check rejected the returned error object, so a test that only asserted `is_valid()` could not tell the difference; asserting the exact
error message killed it. This is the same slip class as DEFECT-001 and shows the operator is useful. The operators are narrow (RuleBoundaryShift matched only 4 comparisons),
so most survivors came from generic core operators.

## Analysis of all 113 round-1 survivors (full per-mutant table in the CSV)
| Category | Count | Meaning |
|---|---|---|
| Killable - missing test or weak assertion | 100 | killed in the final round by the tests named in the CSV rationale |
| Equivalent | 13 | still alive after targeted tests; justified below |

Root causes of the 100 (feeds the defect/RCA section): (1) tests used zeros and tiny numbers where bitwise operators equal addition (1+2 = 1|2 = 1^2; 3-1 = 3^1) - all 40 `stats.py` survivors and several in `common.py`;
(2) optional and boundary form fields never tested with empty or limit values; (3) default parameters never exercised because callers pass every argument;
(4) one participation state tested where the code distinguishes five; (5) tests that asserted only validity or page title, not the specific result;
(6) preference/initial-value logic of the event form tested with coinciding data; (7) atomic `save()` never tested with a failure.

### The 13 equivalent mutants
| Module:line | Mutation | Why equivalent |
|---|---|---|
| participant_validation:47 (x2) | negate `if not shift.event.active` | **Masked by DEFECT-001**: the checker returned its error instead of raising, so the outcome was discarded. After the fix (PR #2) CI killed them: 118/118. |
| structure_common:14 | `TYPE_CHECKING` switch | typing-only; classes inherit the base anyway |
| structure_common:83, 84, 176 (x3) | `-1` offsets in `max(0, x)`, `x or -1`, `max(x or 0, y or 0)` | result clamped to >= 0 by the surrounding `max` / `range` |
| structure_common:134 | remove `@staticmethod` | method is always called through the class, never bound |
| structure_common:177 (x3) | `<` to `<=`, `!=`, `is not` | `list * n` with n <= 0 is empty, so outcomes are identical |
| forms/events:168 | `values_list("user", flat=True)` -> `flat=False` | used inside a subquery; Django uses the single column either way |
| forms/events:267 | `<=` -> `<` on `{"meeting_time","start_time"} <= set(cleaned_data)` | `cleaned_data` always has more keys than the two tested, so the sets are never equal |
Equivalence is argued by reading the code, not formally proven. One prediction was wrong and is recorded: forms/events lines 212 and 226 (`and` -> `or`) were first judged
equivalent and were actually killable (a test that each installed flow is offered exactly once kills them).

## Second batch: four more modules (528 mutants) - INTERIM, 2026-11-25
Same method (Cosmic Ray, isolated workdir, round 1 then survivors-only reruns after killer tests). Raw data: `reports/mutation/round{1,2}_{signup_views,participants,signup_forms,models_events}.*`.

| Module | Mutants | Round 1 | After killer tests | Status |
|---|---|---|---|---|
| `core/signup/views.py` | 38 | 23 killed, 14 survived -> **62.2 %** | 34 killed, 3 survived -> **91.9 %** | final; the 3 survivors are equivalent (see below) |
| `core/signup/participants.py` | 88 | 77 killed, 4 survived -> **95.1 %** | 79 killed, 1 survived -> **98.8 %** | final; 1 equivalent |
| `core/signup/forms.py` | 101 | 69 killed, 31 survived -> **69.0 %** | round 2 running (88 of 101 done, 1 survivor so far) | **in progress** |
| `core/models/events.py` | 301 | 209 killed, 73 survived -> **74.1 %** | round 2 queued | **in progress** |

Why round 1 was low for the view and the form: the existing tests asserted outcomes but not side effects such as the customise notification to responsibles (9 survivors on one line),
comment visibility, atomic saves and locked time fields; 11 form survivors were only alive because that module's mutation test command had not included the unit test that already covered them.
`models/events.py` survivors are mostly model-field definitions (the test database is built from migrations, so max_length/null/blank/default changes were invisible until `full_clean` was asserted),
the rule that a participation grants event view access (14 mutants, never tested) and `|` -> `^` variants in the participant-visibility query.
One custom-operator mutant survived here as well (`RaiseToReturn` in `AbstractParticipation.participant`) because a test asserted only that `str()` was truthy.

Equivalent survivors so far: views line 81 and 82 (`or` -> `and` on the quick-action defaults, whose individual times are only forwarded to plugin signal receivers and ignored by the core flows) and line 142 (`==` -> `<=` while "customize" is the alphabetically smallest valid choice); participants line 115 (redundant `@dataclass` on a subclass that adds no fields).
The final numbers and the per-mutant table for all eight modules replace this section when the remaining runs finish.

## CI gate threshold (justified from this evidence)
Gate: kill rate on `participant_validation.py` >= **90 %** (`scripts/check_mutation_score.py --min 90`, job `mutation-score`).
Round 1 gave 91.4 %, the final round 98.3 %, and CI after the DEFECT-001 fix 100 % (118/118). 90 % blocks a real regression (deleting a killer test drops below)
without failing on equivalent mutants; a 100 % gate would be impossible because equivalent mutants exist.

## Limitations
- Mutation was run on four modules, not all 16 covered modules (about 1 hour per 300 mutants on this machine). Not mutated: `models/events.py`, `signup/views.py`, `signup/forms.py` and the other signup-path modules.
- Equivalence of the 13 survivors is argued, not proven.
- Cosmic Ray core operators were used unfiltered; some mutants (e.g. bit-shift for `+`) are unrealistic.
